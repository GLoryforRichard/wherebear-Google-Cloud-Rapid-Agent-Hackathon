## 1. 成本实验室(/cost-lab + /compare 底部展示)

把 rows-hd 管线拆成三个可独立换模型的环节,逐一换廉价模型与全程 gemini-3.6-flash 基准对比。
**判定方法**:与「基准自己重跑一次」的差异(噪声底线)相当 = 同效。基准照噪声底线:框覆盖 92%/名称一致 98%/清单 Jaccard 87%。

**线上展示**:<https://wherebear.help/compare> 页面底部(服务器实测数据,带框图+清单+分环节成本);独立页 `/cost-lab`。

| 方案 | 成本/张 | vs 基准 | 判定 |
|---|---|---|---|

| **推荐混合:只换读名→2.5-flash-lite** | **$0.110** | **-27%** | ✅ 同效 |

### 三个花钱买来的教训
1. **行检测别换廉价模型**:lite 行检测多切条带(7→8),框选成本反涨,总价几乎不降(反例保留在页面)。
2. **flash-lite 不能胜任框选**:条带输出解析失败,覆盖不完整。
3. **Qwen 系必须加坐标适配层**:惯用 x-first 无视 y-first 提示词,首轮框全转置成横条;纯代码转置(`lib/costlab/transport-lab.ts` 的 `swapBoxOrder`)修复。

## 3. Flex 半价档改造(已上线生产)★ 本次主体工程

### 关键事实(全部实证)
- Flex 是**同步 API 服务档位**(非批量上传):目标延迟 1–15 分钟,高峰被抢占(429/503),需长超时+指数退避;**与标准档共享 RPM/TPM 配额**。
- ⚠️ Vertex 上 SDK 的 `serviceTier` **被静默忽略**(js-genai #1468),必须用请求头 `X-Vertex-AI-LLM-Shared-Request-Type: flex`;静默失效=按全价扣,**账单是唯一硬证据**。
- ⚠️ **undici 陷阱**:Node 默认 headersTimeout 300s 会杀掉排队中的 flex 调用,必须用 SDK `httpOptions.timeout`(会提升 undici 上限),外挂 AbortController 无效。

### 架构(4 个自包含 commit,全部已推 main 并部署)
| Commit | 内容 |
|---|---|
| `80b81d1` | flex 传输层 `lib/scan/transport-flex.ts`:独立泳道(绝不进标准闸门,防饿死搜索/语音)+ 专属重试引擎(2s→60s 退避,30min 总墙钟)+ 半价计价 |
| `857960d` | 异步任务队列:`POST /api/vision/jobs`(**按照片 sha1 幂等**,重试不重复计费)→ Mongo `scan_jobs`(只存状态,照片在 VM 磁盘,产物 result.json 磁盘,M0 512MB 装不下)→ instrumentation 后台 worker(租约+心跳+毒照片防线 attempts≤3)→ 轮询/确认路由。同步 `/api/vision` 保留作回退 |
| `1dd724b` | 客户端泵:提交→5s 轮询;429 队列满=背压不计尝试;**刷新/锁屏恢复轮询而不是重跑**(消灭了"硬杀重计费一次"的旧疮);队列页显示真实阶段 1/4~4/4 |
| `81ac13e` | 保存路径别名扩展切 `GEMINI_ALIAS_MODEL=gemini-3.6-flash`(与搜索/语音共用的 VISION_MODEL 解耦,后者不动) |

### 生产实测(2026-08-09 VM)
- flex 单调用 7.3s(深夜);单张全管线 60–86s;**双照片真并行**(两张同时在框选阶段),内存余量 2.5GB。
- **幂等实锤**:同字节重复提交直接返回已完成任务。
- **隔离实锤**:flex 跑批期间搜索 11–12s(正常水平)。
- **记账**:op_events 每单带 `tier=flex, estimatedCostUsd $0.062–0.076/张`(半价估算)。
- VM 闸门实值 `GEMINI_MAX_CONCURRENT=14`(`lib/gemini.ts:52` 注释写 12 是旧的)。
